## Overview

CloudSSH establishes two encrypted segments between the browser and the target server: HTTPS/WSS from the browser to Cloudflare, then a complete SSH-2.0 session from the Worker through a native TCP Socket. Each active session is managed by an isolated Durable Object, so no traditional VPS relay is required.

Core capabilities include:

- A pure TypeScript SSH-2.0 stack with password, Ed25519, ECDSA, and RSA private-key authentication.
- An xterm.js multi-tab terminal with live latency, search/export, and desktop/mobile support.
- A visual SFTP v3 manager with batch operations and queues, plus trzsz file transfer.
- GitHub OAuth, saved servers, tag filtering, TOFU host verification, and encrypted credential storage.
- A BYOK AI operations assistant with terminal context, eight tools, and command confirmation/blocking.
- Theme V2 presets, custom JSON imports, and signed-in theme synchronization.

Visit the [project site](https://newbietan.github.io/CloudSSH/?lang=en-US) for the complete visual overview. See [AGENTS.md](AGENTS.md) for the implementation map and maintenance constraints.

## Quick deployment

### Cloudflare Git integration (recommended)

1. Fork this repository.
2. In Cloudflare Dashboard → Workers & Pages, create a Worker and connect the fork.
3. Set the build command to `pnpm run build:frontend` and the production branch to `main`.
4. Use the generated `workers.dev` hostname, or bind a custom domain under Settings → Domains & Routes.

The repository's Durable Object migration initializes `SSHSessionDO` and `UserDBDO`. Do not delete an existing Worker during upgrades; new Durable Object classes or schema migrations require a new migration tag.

### Wrangler CLI

Node.js, pnpm, and a Cloudflare account are required:

```bash
git clone https://github.com/newbietan/CloudSSH.git
cd CloudSSH
corepack enable
pnpm install --frozen-lockfile
npx wrangler login
pnpm run deploy
```

The test environment uses a separate Worker and isolated Durable Object data:

```bash
pnpm run deploy:test
```

### Optional configuration

Add these values as needed under Cloudflare Dashboard → Worker → Settings → Variables and Secrets:

| Variable | Purpose |
| --- | --- |
| `TURNSTILE_SECRET` / `TURNSTILE_SITEKEY` | Enable Turnstile verification |
| `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET` | Enable GitHub OAuth and saved servers |
| `BASE_URL` | OAuth site root, such as `https://ssh.example.com` |

Set the GitHub OAuth callback URL to `<BASE_URL>/api/auth/callback`. Store keys as Secrets. Anonymous SSH connections remain available when these variables are omitted.

## Local development

```bash
pnpm install --frozen-lockfile
pnpm run dev
```

Common quality checks:

```bash
pnpm run typecheck
pnpm test
pnpm run test:e2e
pnpm run verify
```

The production frontend build inlines the Vite output into `src/worker/html.ts`. This file is generated by `scripts/build-html.js`; do not edit it directly.

The Pages landing page lives in `docs/index.html`, and the theme editor lives in `docs/theme-editor/`. After changing Theme V2 presets or the landing-page social preview, run:

```bash
pnpm run sync:theme-editor
pnpm run build:pages-og
```

## Security and privacy notes

- Enable Turnstile for public deployments and restrict access to the Cloudflare account and GitHub OAuth App.
- Verify the server's SHA-256 Host Key fingerprint on first connection. Investigate unexpected changes before accepting them.
- Saving a server sends its host to the third-party IPinfo service for region inference and Durable Object placement; failures fall back to Cloudflare's default placement.
- Deployers are responsible for reviewing the code, protecting secrets, and meeting the security requirements of their environment and target servers.
