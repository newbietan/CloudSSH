# Agent 本地上下文紧凑化与长期记忆

## 方案与通用兼容性

CloudSSH 由 SSHSessionDO 本地管理有界会话历史，不使用 `previous_response_id` 或 Conversations 服务端历史，完全基于标准无状态 Responses API（`POST /responses`，强制 `store:false`）。

- **彻底消除脆弱的扩展依赖**：市面上大部分第三方中转站及非 OpenAI 服务商并不支持 `/responses/compact` 独立端点，或无法反解服务端私有加密 compaction 对象。CloudSSH 自建应用层紧凑化机制，完全运行在通用标准 `/responses` 之上，保证 100% 广泛兼容所有 Responses 服务商。
- Base URL 填写 HTTPS 根地址或完整 `/responses` 地址。更换服务商/模型/密钥后须新建 Agent 会话，防止跨配置混用。
- “本地管理”不是本地推理：当前请求内容仍发送给配置的服务商。`store:false` 和无状态接口不能替代对实际留存政策的核查。

## 应用层上下文紧凑化契约

1. **智能边界切分**：当会话接近上下文预算阈值时，`context.ts` 的 `splitForCompaction()` 会逆序扫描完整事务边界，将历史拆分为：
   - **早期交互前缀（toSummarize）**：超过保留窗口的较早用户诉求、助手回复与工具交互。
   - **近期完整尾部（toRetain）**：保留最近 1~2 轮完整交互（近期命令输出、真实报错与助手分析），绝不在未闭合的工具调用中截断，彻底避免全量摘要化带来的近期操作“失忆（Amnesia）”。
2. **高密度事实摘要生成**：将早期前缀格式化为高信息密度文本，使用标准 `/responses` 端点与专用 `COMPACTION_PROMPT` 指令生成纯事实陈述（低推理预算，输出上限 1500 Token）。
3. **权威事实与精确约束注入**：紧凑化段落包含三层不可篡改保障：
   - 早期事实摘要：`[UNTRUSTED OBSERVATION: context summary]`
   - 用户原始诉求与精确约束：`[UNTRUSTED OBSERVATION: preserved user requests]`（累计≤96KiB 约束保证不丢失）
   - 不可回滚的完整执行事实账本：`[UNTRUSTED OBSERVATION: execution facts]`（由 `ExecutionJournal` 权威提供所有已执行命令的精确退出码与状态）
   - 近期完整交互尾部（toRetain）原生回传
4. **平滑降级与失败保底**：
   - 压缩与一次模型调用共享 60 秒 deadline，并受用户取消边界保护。
   - 若模型生成摘要暂时失败或超时，系统自动平滑降级为**本地执行事实保底摘要**继续推进，不中断用户主任务，更绝不自动重跑已执行的远端命令。
   - 仅当续接总预算严重不足以容纳必需执行事实时，才安全暂停任务并保留旧上下文。

### 预算与有限性

- 默认上下文/普通生成输出预算为 64,000/8,192 Token（输出含推理）。
- 当前 UTF-8 字节预算是保守估算，不是通用 tokenizer。
- 保留 2MiB 当前序列化上下文、3MiB 编辑快照预算、96KiB 累计精确用户请求与有界执行账本。不保证无限长会话。
- 会话历史与摘要属于当前 SSHSessionDO 的内存状态；长期记忆与中断检查点另行持久化。

## 三种状态分开管理

| 状态 | 来源与用途 | 生命周期 |
| --- | --- | --- |
| Responses 会话历史 | 原生 items、工具结果与近期完整交互观察 | 当前 Agent 会话，有界内存 |
| 执行事实/工作记录 | 程序确定性记录状态、调用标识、脱敏命令摘要、退出码与时间 | 每任务记录，最近 10 条工作日志 |
| 长期知识 | 模型提议，程序证据筛选、权限与版本校验 | 用户/服务器隔离的持久键值知识 |

### 自然语言工作历程与长期知识提炼

工作记录必须体现完整的运维意图、排查背景与真实结论，拒绝直接拼接截断的代码或机械的机器执行流水。系统将完整上下文（用户诉求、执行命令及关键输出、最终结论，以及最近工作记录）发送给 LLM，提炼为：
1. **工作历程（Work Log）**：
   - 包含自然语言标题与 100~200 字详实总结（阐明用户目的、关键异常特征、所执行操作与最终解决方案）；
   - 支持连续任务识别：在 30 分钟连续排查窗口内，模型可输出 `mode: "update_latest"` 将新成果与前置背景有机融合，避免生成碎裂日志。
2. **知识备忘（Knowledge）**：提取原子可复用参数、规则与凭据。

### 提炼失败持久化与后台异步重试（最多 3 次）

若 LLM 提炼或网络写入暂时失败（例如服务商 5xx、超时或网络抖动）：
1. **本地持久化缓冲**：系统自动将当前任务完整上下文加密保存至 SQLite 表 `agent_pending_distillations`，不因临时失败而丢失事件记忆；
2. **后台异步指数退避重试**：后台异步队列以指数退避延迟自动重试最多 3 次，每次重试均拉取服务器最新内存版本，自动解决版本并发冲突；
3. **果断丢弃保障**：若连续重试 3 次后依然无法成功完成提炼，系统**果断丢弃该待处理任务**并清理 SQLite 记录，杜绝无限失败重试阻塞队列与消耗存储；
4. 提炼成功后，自动从 SQLite 清理待处理记录，并通知前端更新工作备忘列表。

#### 提炼执行规则

1. 入队不复制整份旧记忆/凭据库，执行时读取最新 revision。
2. 按任务相关性提供有限知识；已存凭据在辅助输入中脱敏。用户当前明确提供的值可用于提炼新凭据。
3. 采用低推理提示，首次输出最多 8,192、第二次最多 16,384 Token，并始终受用户普通生成上限约束。Schema 同时写入 instructions，以兼容忽略结构化提示的网关。
4. 本地严格验证整个批次；精确重复项去重，同一 key 的冲突提议整批拒绝，不“取最后一条”。
5. 非敏感新事实必须在用户原文或成功工具结果中出现；凭据只能来自用户原文，不能从失败/未知操作或工具输出猜测。用户手动知识只有在明确要求修改该 key 与新值时才允许更新，来源仍保留为 user；删除必须有明确的忘记/删除记忆意图。
6. 跳过未变化的有效事实。写入本地证据引用（`user` 或 callId）与 taskId，而不是让模型填写证据、时间或有效期。
7. 按预期 revision 原子写入；只对白名单 `memory_revision_conflict` 刷新状态并重新推导，不重发旧批次。普通 409、stale session、HTTP/协议错误不触发冲突恢复。

每个任务最多两次生成，共享一个 25 秒 deadline。第二次机会由“完整结果 JSON/业务格式失败”“明确输出额度耗尽”或“明确 revision 冲突重算”共用，不叠加成多轮重试。内容过滤、未知未完成原因不允许绕过。失败保留旧知识，工作事实记录与主任务不受模型提炼失败影响。

能力学习只在同一 memory manager 和相同配置内复用，不跨用户/服务商共享；reset 清除。队列满、最终冲突和保存失败会显示简短通知，不移除新任务正文。

### 来源与过期

`agent_knowledge_meta` 通过幂等 ALTER 增加 `evidence`、`task_id`、`verified_at`、`expires_at`，不重建现有用户表。

- 有本地证据的自动 config/note：写入后 30 天过期，之后不再自动注入；数据不自动删除，可以经新证据重新确认。
- 用户手动知识、rule、credential：不自动过期。
- 旧知识没有这组时间元数据时，不凭空推断过期时间。
- 检索使用规范键、关键词、有限中文别名、来源与有效性筛选；当前每服务器最多 500 条知识，不引入向量服务。

证据引用表示可追溯的观察来源，不代表远端配置永远有效，也不是执行授权。模型仍需在风险操作前确认，并在未知状态下先验证。

## 存储与诊断边界

内部存储适配器有独立 10 秒 deadline，检查 HTTP 状态；失败读取不能伪装成空记忆，写入失败不能报告成功。加密 await 后重新检查所有权、session/epoch、revision，再在同步事务中提交。客户端取消不能保证已经发出的存储操作绝对没有提交，因此超时提示使用“更新未能确认”，不得盲目重复副作用。

敏感知识和执行事实使用现有 AES-GCM 行级加密。根密钥仍位于同一 UserDBDO SQLite 的 `system_config.encryption_secret`，不是独立 KMS，不能抵御包含根密钥的整库泄露或 Worker 代码执行权限失陷。

普通聊天/通知仅显示简短错误及必要的安全暂停状态。阶段、白名单参数/错误码、本地请求 UUID 和 Token 明细仅在 `DEBUG_MODE=true` 时通过 `type: debug` 输出网页 SSH 终端。任何模式都不输出原始上游错误正文、头部或密钥。
