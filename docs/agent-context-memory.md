# Agent 上下文与服务器记忆

CloudSSH 的 Agent 用于帮助用户部署、配置和维护自己的服务器。记忆的目的，是让后续任务继续使用已有信息，而不是建立审计或证据系统。

## 上下文

- 使用标准 `POST /responses`，固定 `store:false`，会话历史由应用管理；不依赖 `previous_response_id` 或 `/responses/compact`。
- 保留正常对话、工具调用与结果。接近模型上下文上限时，摘要较早对话，并保留近期完整交互继续任务。
- 默认上下文/输出预算为 64,000/8,192 Token，用户可按模型调整。字节估算不是精确 tokenizer，但不能把字节直接当成 Token。
- 摘要请求最多等待 20 秒；暂时失败时使用已有摘要和近期对话继续。无法容纳续接内容时保留原历史并提示调整上下文。
- 历史编辑只修改模型对话，不会撤销服务器上的操作。仍支持停止、替换任务和最近 64 轮编辑。
- 每次任务最多 175 步，不再使用进度评分、循环比例和多轮自动扩展。既有命令确认、连接取消及输出大小限制不变。

## 浏览器中断草稿

Agent 会将最近 20 条中断对话暂存在浏览器 localStorage，供同账号在 30 分钟内恢复界面；正常完成后清理。草稿可能包含对话中出现的敏感信息，因此按稳定的 GitHub 用户 ID（单管理员为 `-1`）和服务器 ID 隔离，不能仅使用各用户数据库中可能重复的局部 ID。

- 未登录或缺少明确用户身份时，不读取或保存草稿。
- 退出账号会销毁原账号面板并清理该账号的所有服务器草稿；换号不沿用原面板，销毁后的迟到消息不能重建草稿。
- 升级后删除旧版没有用户标识的草稿，不自动认领到下一个登录账号。服务器端工作历程和知识不受影响。
- 命名空间用于防止应用换号串号，不是抵御本机浏览器配置文件读取或同源脚本失陷的加密边界。

## 记住并复用配置和凭据

保存的知识、参数和凭据直接提供给后续任务，不进行关键词召回、来源证明、自动过期或程序化脱敏。用户已经给过的密钥，Agent 应直接使用，不重复索取。

- 凭据保存完整原值，包括必要的空格、换行与空密码；不再截断到 256/512 字符。单条值上限为 16,384 字符。
- 界面默认掩码仅影响显示，显示/复制功能和 Agent 使用的都是完整值。
- 延续原有账户存储方式：敏感条目仍使用现有 AES-GCM 行级加密，读取后将原值交给 Agent；没有增加新的密钥管理系统。
- 已有数据继续可读，过去的来源/过期元数据不再参与记忆使用。用户可自行修改或删除知识。
- 所有已保存知识都加入模型输入，仍受模型本身的上下文容量限制；没有额外的敏感信息筛选阈值。记忆过多时可清理不用的条目或增大上下文窗口。

## 工作历程与后台重试

```text
任务完成或中断 → 保存会话 → UserDBDO Alarm 调用 LLM
                                ├─ 成功：保存工作历程/知识，删除待处理任务
                                └─ 失败：最多重试三次，仍失败则删除
```

LLM 根据用户诉求、普通会话中的操作和最终结论生成 `workLog` 与 `knowledge`。工作历程是可读的自然语言总结，不再拼接机器执行流水，也不建立另一份证据包或执行账本。

- 同一连续任务由模型判断是否合并最近工作记录；存储端保留 30 分钟合并窗口。不同任务新建记录。
- 每轮提炼只调用一次生成，不再叠加格式纠正或冲突重算循环。失败统一交给同一个后台重试流程。
- 待处理会话保存在现有 UserDBDO SQLite 中；Alarm 在没有浏览器或 SSH 连接时也能处理，实例重建后继续。
- 每次执行读取当前 AI 配置和记忆版本，不保存旧 API key 快照。首次失败后按 2、4、8 秒重试，最多共四次尝试。
- 单次提炼最多 25 秒。调用前记录尝试次数和下次唤醒时间，进程意外中断也不会无限重试。
- 保存记忆与删除任务在同一 SQLite 事务中完成；重复 Alarm 不重复追加工作记录。不保留租约状态机、完成回执、失败墓碑或诊断审计。
- 没有在线状态轮询。再次打开记忆面板或开始下一次任务时读取已生成的结果。
- 工作记录保留最近 10 条，知识最多 500 项。保留基本字段校验与版本检查，避免无效数据或多标签页写入相互覆盖。

## 实现范围

记忆链路只需要 `core.ts` 提交会话、`memory-provider.ts` 访问存储、`memory.ts` 调用 LLM，以及 `server-memory-store.ts` / `user-db.ts` 保存并重试。

已移除独立执行账本、任务证据包、持久化中断事实检查点、来源/时效规则、复杂召回与授权判定、额外脱敏、双执行队列、通知轮询、租约/回执框架及仅验证这些机制的测试。

这里的“本地”指 Cloudflare 的 DO 内存/SQLite，不是浏览器本地推理。模型请求仍发送至用户配置的服务商，`store:false` 不代替服务商实际留存政策。原有数据库加密根密钥仍在同一 UserDBDO SQLite 中，并非独立 KMS。
